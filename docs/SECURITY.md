# 本地部署安全说明

更新日期：2026-10-29。本说明基于当前源码检查和隔离自动化测试；未做独立渗透测试，未验证真实付费创建、克隆或开机的端到端流程。

## 部署模型与用户隔离

本项目面向每位用户下载后，在自己的电脑和未共享的项目目录中运行。每一份本地服务有自己的状态、专用浏览器、AutoDL会话和可选模型Key，不存在项目自建的共享账号中心、跨用户任务池或远程控制后台。

在上述部署方式下，另一台电脑上普通使用本项目的用户，没有由项目提供的入口读取或操纵你的任务。相同的127.0.0.1地址指向各自电脑，不是所有用户共同连接的一台服务器。

该结论不等于绝对安全。当前没有真正的本机用户认证、多租户权限模型或用户之间的授权隔离。以下情形超出当前保护范围：

- 同一电脑上的其他进程，或有能力连接本机端口的其他操作系统用户，可以读取本地首页并取得本地API令牌。该令牌用于防范浏览器跨来源请求，不证明请求者就是启动服务的用户。
- 获得当前Windows用户权限的恶意程序或恶意浏览器扩展，可能操纵页面、访问服务、读取内存或调用同一用户的解密能力。DPAPI不能防住这种攻击。
- 管理员权限、受感染操作系统、篡改过的安装包和依赖，以及主动共享项目目录或远程桌面，都可能破坏隔离前提。
- 公网、局域网代理或隧道共享本服务不受支持。即使有代理头检查，也不能把它当作服务暴露的安全保障。

如需多人共用部署，需要另外实现账户认证、逐任务授权、会话与凭据隔离、租户数据存储和审计；不能直接将监听地址改成0.0.0.0上线。

## 当前已实现的保护

| 部分 | 实现 | 保护范围 |
| --- | --- | --- |
| 监听 | 正式启动绑定127.0.0.1；请求还需来自回环连接 | 避免直接接受其他电脑的连接 |
| 本地来源 | 校验Host名称和实际端口，核对Origin与Fetch Metadata，拒绝转发头及异常请求目标 | 限制普通恶意网页、跨端口页面与DNS重绑定常见路径；不能认证本机进程 |
| API令牌 | 每次进程启动产生32字节随机令牌，注入本地首页，API请求必须携带 | 浏览器跨来源控制请求的防护；本机可读取首页的进程也可取得令牌 |
| 页面 | 同源CSP、禁止嵌入、静态文件白名单、不缓存、输出转义 | 限制嵌入、脚本注入及静态文件越界；不保证浏览器扩展可信 |
| 请求正文 | 控制接口要求JSON对象，限制请求大小 | 拒绝错误或过大的结构化请求 |
| 凭据显示 | 公共接口脱敏，Key与Token输入保存后清空，留空保留已有设置 | 减少页面和日志意外泄露；不是防御同用户恶意代码的手段 |
| 记住凭据 | 主动选择记住的模型Key、余额Token与通知秘密使用Windows DPAPI CurrentUser保存；失败不降级为明文 | 保护状态文件中的秘密。其他系统暂仅支持内存使用；浏览器资料不由这套Key加密逻辑处理 |
| AutoDL登录 | 在专用浏览器官方页面由用户本人登录与完成验证，不采集密码、不导出Cookie给模型 | 减少密码接触；浏览器仍会按其机制在本机保存会话，目录需按敏感资料保护 |
| 自动付费 | 默认只通知；自动执行需明确费用授权，提交前核验配置与报价；可选余额保护 | 限制误操作。预算估算不是消费封顶，余额保护依赖用户提供同账号的有效Token |
| 提交记录 | 点击前持久化，提交结果不明时对账，不重新创建 | 降低重复付费风险；不是平台服务端事务或绝对幂等保证 |
| 可选AI | 无Key可用；每次分析需确认发送，模型只给建议，不能获得执行实例的接口权限 | 降低模型内容引发直接云操作的风险 |

## 外部数据流

核心网页操作连接AutoDL。配置余额Token后，会调用余额接口；主动启用微信或Webhook后，会把任务通知发送给对应接收方。启用外部渠道后可能重试尚未投递成功的真实任务历史消息；旧演练消息不会发送。

模型默认关闭。启用后，仅在用户提交分析且确认发送时，将表单中的需求、项目资料和报错等允许内容发给所选模型API；不会自动提供AutoDL密码、浏览器Cookie、余额Token或通知凭据。用户粘贴进分析表单的秘密也会成为输入，所以不要将不该交给接收方的信息填入表单。

自定义模型Base URL、Webhook地址和所填凭据由用户决定。HTTPS传输不能证明接收方值得信任。恶意接收方可以记录你主动发给它的内容和对应凭据。当前本地工具允许用户自行配置这些出口，不是通用的多租户SSRF隔离环境。

## 本地文件与分发

.runtime保存任务状态、提交回执、日志、通知以及专用浏览器资料。已选择记住的秘密为密文，但任务元数据、实例ID、日志等不保证加密。Git忽略规则不能阻止手工压缩时夹带文件。

分发项目时不要包含.runtime、浏览器资料、自己的Key/Token或个人备份。每位用户应在自己有权限保护的目录运行；Windows上的创建权限mode参数不等于已经设置了独占ACL。不要假设桌面共享目录或多账户电脑上的loopback端口能隔离其他本机用户。

凭据通常不能跨电脑或Windows用户解锁，迁移时应重新配置。保留含提交回执的状态，避免因删除状态而丢失重复创建保护。备份也应按敏感资料保护。

## 退出、清理与收费

“退出AutoDL”会暂停本地真实任务、关闭专用浏览器并清除本项目浏览器登录资料。可以同时选择清除AI Key、余额Token和通知秘密。退出本项目不撤销其他设备会话，也不撤销平台Token；需要时到对应服务自行撤销或轮换。

关闭监测台、暂停任务、退出登录和清除本地Key均不会关停已创建的云端实例，也不会停止其费用。旧演练记录只停用并保留，不会转换成真实任务。

## 当前验证范围

访问控制、凭据落盘与脱敏、旧演练迁移和禁止调度/通知、付费授权以及核心状态机有自动化回归；浏览器回归使用临时目录和合成会话。具体命令与结果以TEST_REPORT.md最新章节为准。

没有进行真实AutoDL账号的攻击测试、验证码绕过、真实付费提交或第三方安全认证。发布给用户时应准确说明这些边界。
