# 详细使用说明

> 快速上手见 [README](../README.md)。本文是完整说明：两种模式、接入账号与登录、CUDA 兼容、余额预检、AI 环境与选卡、价格与时效、通知、数据保留与安全边界。


本地运行的中文监测工具，仅连接真实 AutoDL。由用户选择 GPU 精确型号，提供新建实例、同地区迁移克隆两种模式。新任务默认找到空闲 GPU 后自动创建并开机（需勾选费用授权），也可选“只通知，停在提交之前”。

**AI 环境与选卡是可选功能：粘贴项目资料，算出这个项目能在哪些 GPU 型号上跑、各地区空闲多少，一键填入新建任务。规则部分不需要模型；需要模型时填写自己的 API Key（DeepSeek、阿里云百炼等）。没有模型也能完成 GPU 监测、新建、克隆和通知；使用者的电脑无需 GPU。**

**当前交付已通过自动化测试和本地合成页面回归。真实账号上：2026-10-29 自动新建并开机（RTX 4090 × 1）；2026-10-30 凌晨克隆 RTX 5090 → RTX 5090（不复制数据盘）完成，克隆 RTX 4090 → RTX 5090（复制数据盘）已创建并绑定目标实例（之后用户手动释放了该实例，见 TEST_REPORT）。数据盘复制完成的判断和多数报错/弹窗的真实页面情况尚未验证。不确定当前页面时，可先用“只通知，停在提交之前”核对。**

## 启动

简明的安装、启动与使用步骤见 [安装与使用说明.md](../安装与使用说明.md)。

Windows 双击本目录的 `启动监测台.cmd`，然后在浏览器打开终端显示的本地地址，默认是 `http://127.0.0.1:8787`。

也可使用 PowerShell：

```powershell
npm.cmd install
npm.cmd start
```

需要 Node.js 22 或更高版本。本地控制台可直接打开，建立任务前必须登录 AutoDL 并核验会话。项目使用独立浏览器保存登录。程序优先尝试已有的 Playwright Chromium；Windows 未安装时会尝试本机 Edge。其他情况可执行：

```powershell
npm.cmd run browser:install
```

如需要明确使用 Edge，在启动前设置 `$env:AUTODL_BROWSER_CHANNEL='msedge'`；Chrome 对应 `chrome`。改变端口可设置 `$env:PORT='8788'`。程序只监听本机 `127.0.0.1`。

保持电脑联网、唤醒，保持 Node 服务和专用浏览器运行。关闭终端、结束服务或电脑休眠都会中断监测。关闭控制台网页不影响后台检查，但桌面提醒需要网页保持打开。

后台与网页是分开的：**关闭网页不会停止后台，后台已在运行时再次双击 `启动监测台.cmd` 也不会替换它。** 这时启动窗口会说明正在运行的后台是哪个 PID、是否为当前代码以及如何重启，不会再启动第二份（防止两个程序同时抢卡）。磁盘代码已更新、后台支持正常停止时，在该窗口输入 Y 即可让旧后台正常停止并用当前代码重新启动。停止请求没有收到回复时，程序不直接放弃：先核对运行锁和端口，旧后台已开始停止就等它退出后启动新后台；旧后台仍在正常运行才重发一次请求；被拒绝时写明 HTTP 状态和原因。全程不强制结束进程、不删除运行锁。

更新代码后需要重启本地后台：先暂停监测并等待正在提交或核验的操作结束，在原启动终端按 Ctrl+C 正常停止服务，或在项目目录运行 `npm.cmd run stop`（后台会等当前页面操作结束、保存状态、关闭专用浏览器后退出），再重新运行 `npm.cmd start` 或双击 `启动监测台.cmd`，最后刷新网页。直接关闭启动窗口也会按正常停止处理。停止恰好发生在点击“创建并开机”之前时，本轮不点击，任务不会转为“需要处理”，重启后继续监测。仅刷新网页可能出现新版前端调用旧后台、提示“接口不存在”的情况；不要删除 `.runtime`、运行锁或浏览器资料来处理此错误。重启后重新打开专用浏览器并检查登录状态，再读取报价。控制台顶部若出现“本地后台仍是旧版本”或“磁盘上的程序已更新，但本地后台仍在运行启动时的代码”，说明需要按此步骤重启。

若后台是被脚本以隐藏窗口启动的旧版本（找不到可按 Ctrl+C 的终端，`npm.cmd run stop` 提示旧版后台不支持），先在控制台确认没有“提交中/验证实例与数据/等待绑定核对”的任务，再在任务管理器“详细信息”中按 PID 结束该 `node.exe`。PID 可在 PowerShell 用 `Get-NetTCPConnection -LocalPort 8787 -State Listen` 的 `OwningProcess` 查到，确认其命令行是本项目的 `src/server.mjs`。强制结束不会撤销已创建的云端实例；状态文件为整体替换写入，提交边界在点击前已落盘，重启后按原规则对账。专用浏览器窗口若未随之关闭，请手动关闭后再启动，否则新后台无法使用同一浏览器资料。之后在可见终端运行 `npm.cmd start`，便于下次用 Ctrl+C 正常停止。

## 两种模式

| 模式 | 需要填写 | 命中后的行为 |
| --- | --- | --- |
| 新建实例 | 用户选择的 GPU 精确型号、数量、一个或多个地区、同步并选择官方基础镜像（CUDA 自动带入）、扩容容量，读取官方配置报价 | 重新核对库存与结算费用，创建并开机，验证目标实例，通知 |
| 迁移克隆 | 同步并选择已关机源实例；地区固定为源实例所在地区，目标 GPU 型号和数量默认与源实例相同、可以更换；选择扩容和是否复制数据盘，读取官方配置报价。不需要填写 CUDA、Python、PyTorch | 排除源主机，克隆系统盘，可选复制数据盘；创建并开机，核验运行状态及所需复制状态，通知 |

GPU 型号从 AutoDL 创建页按地区同步（见下方“同步 AutoDL 型号”），下拉框只列出所勾选地区有的型号；列表里没有的显存或版本变体可选“其他型号”填写官方完整名称。不会默认使用或自动回退到 RTX 4090。

登录核验通过后，点击“同步实例”读取当前账号实例。在实例卡片点击“用作克隆源”，或从克隆表单的源实例下拉框中选择，地区会锁定为源实例所在地区，GPU 型号和卡数带入源实例的规格。运行中、状态不明确、型号或地区无法识别的实例不能用于自动克隆。服务端在入队与提交前重新读取源实例，不依赖前端；源已删除、开机或换了地区时停止。实例列表按需同步，控制台轮询只读取缓存。地区仍限项目内置范围，未知新型号可能需要补充页面解析后才能使用。

迁移只支持源实例所在的**同一地区**（AutoDL 克隆页只允许源实例所在地区）。“同时复制数据盘”默认勾选，目标额外扩容至少等于源额外扩容；取消后仅克隆系统盘，源数据盘文件不会复制，目标数据盘按用户填写的扩容配置。两种选择都会保留源实例及源数据盘。切回新建模式时，会恢复之前选择的 GPU 型号、卡数和地区，新建仍支持多地区。

### 克隆到其他型号

AutoDL 的克隆页可以选同地区的任何主机，所以目标 GPU 型号和数量可以与源实例不同。克隆会原样复制源实例的系统盘，Python、PyTorch、CUDA 等环境与源实例完全相同，因此不需要填写。程序在首次检查时从 AutoDL 克隆页读取源实例镜像的 CUDA 版本，写进任务日志，只选宿主驱动支持该版本的主机。

环境能否在另一种 GPU 上运行，取决于源实例里装的框架是否支持这种 GPU 架构。程序会检查 AutoDL 下单前也会检查的一条规则：Blackwell 架构（如 RTX 50 系列）需要 CUDA 12.8 及以上。源环境低于 12.8 时，这类型号的主机不作候选，读克隆页时就停止并说明。其他架构由 AutoDL 下单前的提示把关：出现这类提示时程序不会代为点“继续”，确认未创建后停止任务并写明原因。PyTorch 是否带有该架构的支持，程序无法从外部判断，换型号后请先运行一次最小测试。

### 源实例只读保护

克隆时程序对源实例只做读取，不改动任何东西：

- 只点三处：源实例所在行的“更多”、菜单中的“克隆实例”、克隆对话框中的“继续”。每次点击前再读一次元素文字，必须完全一致才点；源实例所在行在点击前也会再核对一次实例 ID。开机、关机、无卡模式、释放、重置系统、更换或保存镜像、升降配置、扩缩容、转计费方式、跨实例拷贝、修改 SSH 密码等操作，程序里没有任何点击入口，`tests/source-protection.test.mjs` 会检查这一点。
- 克隆对话框中只按任务设置勾选或取消“数据盘”（只影响新实例）。对话框里看不到 AutoDL 的“克隆后源实例不受影响，不会释放也不会清理数据”说明、选中了“克隆给他人”、“继续”不可用时，停止且不继续。
- 跳到克隆页后核对地址：源实例 ID 必须与任务一致；数据盘复制与任务设置一致；不允许把源实例的自定义服务地址转给新实例。点击“继续”只打开克隆页，不下单；只有点击克隆页上的“创建并开机”才会创建新实例。
- 克隆页地址在内存中保留约10分钟，期间直接打开，不再反复展开源实例的菜单。地址不对时重新走一遍菜单。
- 程序不会开关机源实例。克隆要求源实例已关机；源实例被开机时，提交前的复核会发现并停止。

复制数据盘期间请不要开机或改动源实例，以免复制失败。

以上依据 2026-10-29 读取的 AutoDL 公开前端代码（克隆对话框与克隆页）和本地合成页面测试，尚未在真实克隆页上完整走通。

选择复制数据盘时，GPU 开机和数据复制分别核验。平台页面没有明确显示数据盘复制完成时，程序继续等待，超过30分钟（从点击“创建并开机”算起）提示处理；在“需要处理”时点“恢复检查”会重新等待30分钟，复制完成后自动完成。也可以登录目标实例检查数据盘目录、文件数量、关键文件与必要的校验和，确认完整后在任务详情中提交“人工数据核验”。复制未完成前不要向目标数据盘写入。未选择复制数据盘的任务，在目标 GPU 运行核验通过后即可完成，不等待数据盘复制。

## 处理旧任务冲突

新建任务按 GPU 型号、克隆任务按源实例防止重复执行。提交时遇到冲突，页面会保留当前表单，展示原任务的状态、CUDA、地区与失败原因；可查看原任务与日志。

原任务处于“需要处理”或“已暂停”，且尚无提交记录和目标结果时，可点击“停止未提交旧任务并按当前配置重建”。服务端重新校验配置、源实例与所选余额保护，通过后一次保存新任务和旧任务的停止状态，原配置与日志保留。若原任务已恢复、校验失败或保存失败，旧任务保持原状。新任务沿用当前表单的执行授权，找到符合条件的资源后按任务设置自动提交、核验并通知，不会先停下来等待开机确认。

已有提交记录的任务继续保留防重保护，即使曾被停止，也应先核对目标实例。旧版后台不支持重建接口时，弹窗会提示先正常重启服务，不会先停止旧任务。

点击“创建并开机”后结果不明的提交，监测中的任务会在点击约2分钟后自动核对（见“没抢到时”）。已停止的任务不再自动核对，它的提交记录会一直阻挡同型号或同源的新任务，停止本地任务也不会解除。这时打开原任务详情：

- 平台确实创建了实例：在“填写此次创建的目标实例 ID”中绑定，程序继续核对该实例（已停止的任务也可以绑定）。
- 没有可绑定的新实例：点击“重新核对实例列表”。程序只读重新读取当前账号的完整实例列表，全部都是提交前已有的实例时，才确认这次点击没有创建实例并清除提交记录；只要有提交前没有的实例，就保留记录并列出这些实例。距点击不足2分钟时不能核对，以免平台仍在创建。清除后可恢复任务或新建同型号任务。

## 只保留真实 AutoDL

控制台已删除运行环境切换、合成库存、虚拟源实例及演练任务入口。后端仅接受 `provider: "autodl"`；传入旧的 `demo` 配置会被拒绝。

旧版本保存在本地的演练记录和回执不会被删除或转换成真实任务。下次启动时，未结束的旧演练会被停用，页面隐藏相关任务与通知；引擎不会恢复执行，通知渠道也不会投递这些旧消息。测试用合成适配器只保留在 `tests/fixtures/`，正式服务不导入它。

新任务默认“自动创建并开机”：找到符合条件的空闲 GPU 后在同一轮内直接提交，提交前必须勾选表单中的费用授权，未勾选时不能建立任务。想先试运行时可改选“只通知，停在提交之前”。只有在用户授权自动执行的任务中，才会进行付费创建或克隆。

## 接入真实账号

本项目面向**每个用户下载后在自己的电脑上运行**，不需要注册本项目账号，也不提供共享的 AutoDL 登录服务。

1. 在“资源监测 → 连接 AutoDL”点击“打开登录”，在弹出的**专用浏览器**中亲自完成 AutoDL 登录及必要的人工验证。日常浏览器中已登录的账号不会自动共享给这里。
2. 回到监测台，点击“检查登录状态”。只有显示**“会话可用”**，才能创建真实任务；仅打开浏览器不算登录成功。账号没有实例时，也可以通过明确的实例列表空态确认会话。
3. 配置通知渠道，保持控制台网页打开。侧栏的“本地服务 已连接”只表示网页连接到了本机后台，**不代表 AutoDL 已登录**。
4. 勾选地区，点击“同步 AutoDL 型号”，从列表中选择 GPU 型号（见下方“同步 AutoDL 型号”）。保持默认“自动创建并开机”时勾选费用授权；第一次使用或不确定页面时，可先选“只通知，停在提交之前”。
5. 若是新建实例，点击“同步官方镜像”，依次选择框架、框架版本、Python（系统）和 CUDA。每一级读取 AutoDL 当前基础镜像菜单；完整路径与 CUDA 自动带入。更换上级会清空下级及旧报价，界面不预填或拼接版本。
6. 若是迁移，点击“同步实例”，选择已关机源实例。地区会锁定为源实例所在地区；目标 GPU 型号和卡数默认与源实例相同，可以更换（见“克隆到其他型号”）。选择是否复制数据盘。CUDA 不需要填写，首次检查时从源实例读取；复制数据盘时还需核实源扩容，无法确认必要条件会停止处理。
7. 建立任务。自动执行任务按该任务的配置执行一次提交；没抢到时继续监测（见“没抢到时”）。

### 同步 AutoDL 型号

不同地区可租的 GPU 型号不同。点击“同步 AutoDL 型号”后，程序在专用浏览器中另开一个标签页，打开创建页并选“按量计费”，逐个点选本项目支持的6个地区，读取页面“GPU 型号”筛选中的型号及括号内的数字，读完即关闭该标签页。只读取页面，不提交表单，也不改动监测任务正在使用的页面。6个地区约需十几秒；有监测任务运行时，会等当前一轮检查结束（最多20秒）再读取，读取期间该任务暂停检查。

- 型号下拉框只列出所勾选地区有的型号。勾选多个地区时列出合集，并按地区标出数字，例如“RTX 4090（北京B区 2/8，西北B区 0/16）”。
- 括号内是同步时页面显示的“空闲/总数”，不是实时库存；监测时每一轮都会重新读取页面。说明里写明同步时间和距今多久（例如“38 分钟前”）。
- 每次“检查登录状态”通过后，网页自动刷新一次型号目录，不必手动点同步；同一次登录只刷新一次。刷新期间监测任务暂停约十几秒，刷新没完成时（例如页面正忙）说明里会提示，可稍后手动同步。
- 同步结果保存在本机 `.runtime/state.json`，重启后仍可选择；平台增减型号后重新同步即可。某个地区读取失败时，其他地区照常保存；一个型号都没读到时保留上次的结果。
- 已选的型号在重新同步或更换地区后不在列表中时，选择保留并标注“所选地区当前未列出”，不会换成别的卡。
- 克隆任务的型号默认取源实例，可以改选该地区列表中的其他型号。源实例型号不在该地区的同步列表中时照样保留，并提示核对。
- 多地区任务运行时，某个地区的型号筛选中没有该型号，就跳过这个地区，日志写“没有此型号，已跳过”；所选地区都没有时才报错停止，不改用其他型号或地区。

AutoDL 文档中还有本项目未支持的地区（如企业区、专区），同步只覆盖项目内置的6个地区。

### 同步官方基础镜像

新建表单提供四级联动选择，选项来自已登录专用浏览器中 AutoDL 创建页的可见基础镜像菜单。点击“同步官方镜像”读取框架，选定每一级后再读取该分支下一级；当前仅支持官方基础镜像。读取在单独的标签页中进行，不覆盖任务正在使用的表单。

“同步官方镜像”每次都重新打开创建页读取最新菜单（本机日志中打开创建页约需3～5秒）。之后选择框架、版本、Python 时，直接在这个已打开的菜单上展开下一级，不再每级重新打开页面；该标签页闲置约2分钟后自动关闭。为确认下一级菜单属于刚选的分支，程序等待所点选项的展开标记出现后才读取；确认不了时自动改为重新打开页面读取，本次运行不再复用。监测任务正在运行时，同步会等当前一轮检查结束（最多20秒）再读取，不再直接提示“页面忙”。镜像同步沿用登录检查与本地访问保护。

四级选择完成后，完整镜像路径和 CUDA 自动生成。CUDA 就是第四级的选择，表单上方不再单独显示一个 CUDA 框；上级变更、重新同步或会话失效会清除相应下级及旧报价，避免沿用其他环境。切换到克隆时无需选择基础镜像，克隆继承源环境；其 CUDA 筛选要求单独填写，切回新建会恢复已选的新建环境。禁用、重名、空菜单或读取失败会提示重新同步，不使用本地写死的版本补足。

2026-10-29 已使用本机现有会话只读核实：当时 `PyTorch / 2.1.0 / 3.10(ubuntu22.04)` 下 CUDA 只有 `12.1`，`PyTorch / 2.8.0 / 3.12(ubuntu22.04)` 下是 `12.8`。实际版本以后续同步为准。把前一个分支手动填成 CUDA 13.0 会在第四级失败，不能用宿主驱动支持 13.0 来证明该镜像存在。

任务执行前仍重新选择并精确核对四级完整路径。镜像下架时显示当前分支可选值，要求用户选择环境并建立新任务；旧任务保留原配置，不自动改成其他 CUDA、Python 或框架版本。若更新后提示“本地后台未加载此功能接口”，按下方正常重启步骤更新后台后再刷新网页。

### 登录状态、核验与隐私

| 状态 | 需要做什么 |
| --- | --- |
| 未打开登录 / 浏览器已关闭 | 打开专用浏览器；程序不会因此删除本机已保存的会话 |
| 登录待检查 | 完成手动登录，再点击“检查登录状态” |
| 正在检查 | 等待结果，不要重复点击 |
| 会话可用 | 当次只读核验通过，可以创建真实任务 |
| 未登录 / 登录已失效 | 回到专用浏览器登录，重新检查，然后手动恢复暂停的任务 |
| 待人工验证 | 在专用浏览器处理验证，完成后再次检查；程序不会代过验证码 |
| 网络访问受限 | 退出旧服务，在普通 Windows 环境双击“启动监测台.cmd”重启，再重试打开登录；见下方网络排查 |
| 无法确认 / 检查未完成 | 查看页面或检查网络后重试；不会把加载中、未知页面或网络故障误报为已登录/登录过期 |

“检查登录状态”会先只读观察现有登录或人工验证页面，保留正在进行的验证和已填内容，不导航、不额外打开验证页。完成登录并跳转后，再打开或复用一个**核验标签页**读取实例列表的正向证据，不会创建、克隆、开机或租用 GPU。请先在原专用浏览器中完成手动登录/验证，再点击检查；不要将核验标签页用于编辑实例。程序不会刷新任务正在使用的标签页；核验标签页若已进入其他表单，会另开核验页。

核验与后台页面操作互斥，繁忙时提示稍后重试或先暂停真实任务，不打断提交。页面的“最近核验”只代表当时结果，**不是会话永不过期的保证**；任务访问页面时仍会检查登录和人工验证提示，发现问题后沿用任务的人工处理/对账机制，不会自动重放不明确的付费提交。普通前端刷新只读取缓存状态，不会每两秒访问 AutoDL。

检测仅使用页面地址、可见登录/验证提示及实例列表的正向证据，不读取密码输入值，不提取或传输 Cookie。会话由本机专用浏览器保存；模型 API Key 与 AutoDL 登录无关。发布或分享项目压缩包时务必排除 `.runtime/`，不能把自己的登录会话和任务状态一起分发。

### 安全验证反复失败

专用浏览器现已显式启用Chromium安全沙箱，登录页面随浏览器窗口尺寸调整。旧浏览器顶部出现 `--no-sandbox` 提示时，需要关闭旧专用浏览器并重新打开才能应用新配置；若后台仍为旧版本，还需要先重启服务。开启沙箱是安全配置修正，不能据此断定验证码失败的原因，也不能保证平台验证通过。

请在原登录页亲自完成安全验证和登录，完成后再回到监测台检查状态。检查操作不会刷新进行中的验证页面或清空已填内容。页面提供“微信登录”时，已绑定的账号也可使用该官方入口。若仍反复失败，可对照本人日常浏览器的官方登录页是否同样失败，将失败提示与时间提供给AutoDL客服；程序不会自动识别或代过验证码。日常浏览器的登录不会自动共享给专用浏览器。

### 打开登录时提示网络访问受限

若点击“打开登录”出现 `ERR_NETWORK_ACCESS_DENIED`、`ERR_ACCESS_DENIED` 或 `ERR_BLOCKED_BY_ADMINISTRATOR`，说明专用浏览器访问网页被启动环境或网络策略拒绝。错误发生在登录页加载阶段，不能据此判断账号或密码错误。监测台会显示“网络访问受限”和“重试打开登录”，不会把这类故障当作登录过期或无限重试任务。

先暂停正在运行的真实任务，等待页面操作结束，再关闭旧服务及其专用浏览器。在文件资源管理器中双击项目目录的 `启动监测台.cmd`，或在普通 PowerShell 中运行 `npm.cmd start`，然后刷新监测台并重新打开登录。**只刷新网页不会更新已运行的 Node 后台代码**。重启保留任务文件和浏览器登录资料；主动选择记住的凭据可在同一 Windows 用户下恢复，未记住的余额 Token 和模型 Key 需要重新填写。若提示已有服务，不要启动第二份或删除运行锁，先确认旧服务已经退出。

可在普通 PowerShell 中运行只读公共网络诊断：

```powershell
npm.cmd run diagnose:network
```

诊断分别检查 Node 与临时无痕浏览器能否访问 AutoDL 公共首页，不启动监测服务、不读取登录资料、不登录或操作实例。2026-10-28 本机对照结果：受限工具环境复现网络拒绝，普通 Windows 环境的 Node 与 Edge 均返回 HTTP 200。公共首页可达不代表账号已经登录；仍需在专用浏览器手动登录并检查状态。如果普通环境仍然失败，再核对代理、防火墙或组织网络策略，无需管理员运行，不建议关闭全局防火墙或禁用浏览器安全隔离。

## 登录与凭据保存

AutoDL 账号和密码在专用浏览器的官方页面输入，项目不提供账号密码表单。浏览器登录资料保存在本机专用目录，下次可继续使用；平台仍可能要求重新登录或人工验证。

AI Key、余额 Token 和通知凭据各有“记住到本机”选项。Windows 下使用 DPAPI CurrentUser 加密后存入状态文件，绑定当前 Windows 用户及电脑；页面恢复时显示“已配置”，模型 Key 和余额 Token 输入框保持空白，不将真实秘密回填到网页。不记住则仅在当前服务中使用；普通模型参数（如输出 Token 上限）、任务和非秘密设置仍会保存。没有安全存储支持的平台禁用记住，不降级明文保存。旧版已记住的明文会在启动时迁移，旧备份不会被自动擦除。

点击“退出 AutoDL”，确认后暂停本地真实任务、关闭专用浏览器并清除其登录资料。可勾选同时清除 AI Key、余额 Token 和通知凭据；默认保留这些独立配置。退出不删除云端实例、不关闭正在计费的 GPU，也不撤销其他设备会话或平台 Token。各模块的清除按钮可单独清除对应凭据。

加密不能防止当前 Windows 用户下的恶意程序或已获系统权限的人获取秘密；专用浏览器资料也须保护。请不要分享 .runtime，泄露后应在对应平台撤销凭据。

## CUDA、Python 与 PyTorch 兼容性

CUDA 字段指镜像/程序需要的 CUDA，宿主页面显示的 CUDA 通常指驱动最高支持能力；二者含义不同。新建精确匹配四级基础镜像路径，最后一级 CUDA 必须与任务字段相同；克隆继承源系统盘中的环境，不自动升级 Python、PyTorch 或 CUDA，CUDA 从 AutoDL 克隆页读取，不由用户填写（旧任务里手填的值不再用于筛选）。

GPU 架构对 CUDA 有最低要求。AutoDL 下单前的提示：安培架构（30 系列、A40、A4000 等）需 CUDA 11.x 及以上，Ada 架构（40 系列、H800 等）需 11.3 及以上，Blackwell 架构（如 50 系列）需 12.8 及以上。本项目按型号名识别 Blackwell：新建时所选镜像 CUDA 低于 12.8 直接拒绝建任务，克隆时源环境低于 12.8 则不选这类主机。

例如要求 CUDA 12.8：宿主驱动最高支持 13.0 时满足本项目的驱动版本门槛，仍须核验 GPU 架构和库；最高支持 12.6 时同大版本可能有受限兼容，但 PTX/JIT、新特性或扩展可能失败，本项目不自动放行。镜像本身为 CUDA 12.6 或 13.0 时不能直接当作指定的 12.8 镜像替换。Python 与 PyTorch 都不存在“版本越高必然兼容”的规则。

官方依据、检查命令与适用边界见 [环境兼容说明](ENVIRONMENT_COMPATIBILITY.md)。

## 账户余额与预算预检

在“账户余额”卡片填写与专用浏览器**同一 AutoDL 账号**的开发者 Token，点击“连接并查询余额”。现金余额和代金券分别显示；Token 仅用于余额接口，不能代替浏览器登录，也与可选 AI 的模型 Key 无关。Token 默认只在当前服务内存中保存；可主动勾选“在本机加密记住余额 Token”，下次恢复连接时不回显原文。清除会同时移除内存和持久化凭据，余额金额仍需重新查询。余额接口本身无法证明 Token 与浏览器属于同一账号，请自行核对。

创建和克隆表单默认勾选“提交前检查账户余额（可选）”，可设置预计运行小时数和保留余额，按需勾选计入代金券，再点击“刷新余额并预检预算”。预检按以下方式计算：

```text
所需金额 = 配置总时价 × 预计运行小时数
         + 磁盘日价 × max(1, ceil(预计运行小时数 / 24))
         + 保留余额
```

先按当前资源、环境和磁盘配置读取完整官方报价，再刷新余额并预检。报价有效期60秒；配置改变、过期或读取失败时必须重取。有有效同配置报价时，余额不足的真实自动任务不能入队；无完整报价时允许先监测，界面标明“等待报价”，找到资源后仍需按最新报价与余额通过检查才能提交。付费提交前刷新余额，并在记录点击边界前再次确认；无 Token、查询失败、余额过期、金额不足或报价未知均不付费提交。余额接口偶尔超时或不可用（不是鉴权失败）时，任务退避后自动重试，连续 5 次失败才转“需要处理”。开启余额保护却没有连接 Token 时，监测阶段就提醒一次，任务继续监测，连接 Token 后自动恢复。AutoDL 规定租用多卡实例时钱包余额（不含代金券）需大于 10 元，不满足时同样提醒并继续监测。代金券默认不计入，只有用户明确勾选才纳入估算，适用性仍以平台结算为准。可以主动关闭该任务余额保护，资源、配置、报价与授权核验仍保留。旧任务继续尊重原先填写的费用上限。

为避免“找到空闲 GPU 却因余额不足提交不了”，自动执行任务在提交之前还会按页面上的单卡价估算一个下限：`单卡价 × 卡数 × 预计运行小时数 + 保留余额`（磁盘费未知时不计，所以只在余额**确定**不够时才拦截）。

- 新建任务时：刚读取的报价里没有完整报价、只有单卡价时，余额低于这个下限就不创建任务，提示先充值。
- 监测期间：没有空闲 GPU 的轮次最多每5分钟查一次余额；余额低于下限时提醒一次，任务继续监测。找到空闲 GPU 时若余额仍不够，跳过这次核验和提交；充值后，下一次找到空闲 GPU 时重新查余额并自动提交，不需要重建任务。
- 按完整报价核对余额不足时也一样：不点击，提醒一次，继续监测。

AutoDL 帮助文档没有写开机需要的最低余额，只写了按量计费“整点扣费一次和关机时扣费一次”、余额不足时“会优先保留实例数据产生计费，不会立即释放”、欠费超50元平台保留删除数据的权利（[计费说明](https://www.autodl.com/docs/price/)，2026-10-29 查阅）。本项目的余额检查是保守预检，不是平台规则；预计运行时长默认1小时，即至少要够1小时 GPU 费用和1天磁盘费。

余额采用按需查询和30秒缓存，页面轮询不会持续请求平台。预算预检不冻结资金，也不是累计消费封顶；预计运行时长不会自动触发关机，其他实例扣费或平台结算变化仍可能改变余额。

## AI 环境与选卡（可选）

打开侧栏“AI 环境与选卡”。上方“环境与选卡规划”回答一个问题：**这个项目能在哪些 GPU 型号上跑**。抢不到某一种卡时，可以知道还能等哪些卡。

1. 粘贴项目的 README 片段、requirements.txt、environment.yml 或报错日志；可写一句“你要做什么”（例如“LoRA 微调 7B 模型”）。
2. 点“分析并选卡”。规则在本机读出明确的写法：`torch==2.1.0+cu121`、`python>=3.8`、`cudatoolkit=11.3`、“需要至少 24GB 显存”、`flash-attn` 等，每条附原文出处。规则读不准的（例如表格里按模型大小、训练方式列出的多个显存数字）标为“待确认”。
3. 对照“同步 AutoDL 型号”得到的各地区目录，逐个型号给出“可用 / 有风险 / 需核对 / 不满足”及原因：单卡显存是否够；GPU 架构对 CUDA 与 PyTorch 的下限（Ampere 需 CUDA ≥ 11.0，Ada 需 ≥ 11.3，Blackwell 如 RTX 5090、RTX PRO 6000 需 CUDA ≥ 12.8 且 PyTorch ≥ 2.7）；FlashAttention 2 需 Ampere 及以上等。认不出架构、或同名有多种显存版本的型号标为“需核对”，不猜。资料没写显存时，按模型大小估算：推理总显存 ≈ 1.2 × 参数量 × 每参数字节（FP16/BF16 为 2，INT8 为 1，INT4 为 0.5），例如“部署27b模型”约 65GB；微调按 LLaMA-Factory 的估算表；多卡按卡数平分；写了 int4 等量化方式时按量化估算。资料有多个显存数字时按最大的判断。显存要求读不出、也估算不了时，所有型号都标“需核对”，不会判为“可用”。
4. 在想等的型号上点“填入新建任务”：填好型号和有这个型号的地区，并在 AutoDL 官方镜像菜单中逐级选好框架、版本、Python、CUDA（选满足条件的最低 CUDA，宿主驱动更容易满足）。仍需你勾选费用授权并提交；提交前的库存、驱动、价格、镜像核对照常进行。一个任务只等一种型号；分别建多个任务时，两边都抢到会各自计费。
5. 结果末尾给出拿到实例后在终端运行的检查命令。克隆到其他型号前，可以在源实例运行其中 `torch.cuda.get_arch_list()` 那一条，把输出贴回来检查目标卡（例如源环境只有 sm_90 及以下内核时，RTX 5090 会报 no kernel image）。

勾选“让 AI 补充规则读不出的约束”后，模型按你的需求从资料中挑出对应的显存、卡数等。模型的每条结果都要附原文片段；程序核对片段确实在你提交的文本里、并含有这个值，否则丢弃并列出原因。依赖文件里的版本以规则为准，模型只填空。模型补充的条件在表格中标为“模型补充”。

模型使用你自己的 API Key：DeepSeek、阿里云百炼，或其他 Chat Completions 兼容接口。在“模型设置”中选择接口类型，填写自己的 Key、Base URL 和模型 ID，勾选启用并保存。模型在服务商那里运行，本机不需要 GPU，也不需要安装任何模型。

- 费用由服务商按 Token 计费。一次规划的请求约 600～1100 Token（评测中 13 个用例的实测值），长资料只把与运行条件相关的行发给模型。
- 发送前要勾选确认；只发送本次表单中的文字，不发送任务记录、账号凭据或数据盘。
- 百炼的千问模型多数默认开启思考，本工具请求时关闭思考（`enable_thinking: false`）；请选择支持关闭思考和非流式调用的模型。DeepSeek 请求时关闭 thinking 并要求 JSON 输出。
- Key 默认只在本次服务进程中保存；可选“记住 API Key 到本机”（Windows DPAPI 加密）。

下方“分析项目或错误日志（文字建议）”是原来的诊断功能，输出文字建议、输入引用与核验方法。

规划与 AI 都不参与库存轮询，不创建或修改任务，不执行命令。未启用、超时、调用失败或取消，核心 GPU 任务继续运行；模型补充失败时仍显示规则结果。评测方法与结果见 [eval/PLAN_EVAL.md](../eval/PLAN_EVAL.md)，Key 的存储与限制见 [可选 AI 使用说明](AI_ASSISTANT.md)。

## 价格和时效

新表单突出显示 **AutoDL 当前页面的单卡每小时价格**，附来源与读取时间；读到完整配置报价后，下方一行再写配置每小时总价（多卡时注明卡数）和磁盘日费；不再把3、4、5等预设上限当成价格。点击“读取 AutoDL 官方报价”只读取库存和配置页，不提交租用。无库存时可能只读到匹配主机的单卡价或范围，配置总价及磁盘日费保持未知，不伪造0元报价。界面分别说明无库存、条件不匹配、页面未读到主机及配置报价读取失败。无完整报价仍可先启用监测；启用余额保护的自动任务需先连接余额凭据，找到资源后读取完整报价并核对余额，再自动提交。预览有效期60秒，配置改变即失效；提交前重新读取并核对实际报价。展示范围仅为当前已读取页面，不是全站最低价保证。

用户授权真实自动执行后，程序按提交时官方报价执行，预览不锁价；预算估算也不是消费封顶。实例创建后会继续运行计费，扩容磁盘也可能按平台规则持续计费。程序不做自动关机，暂停、停止本地任务或退出监测台都不会停止云端计费。旧任务/API 的 limits 策略继续保留原有三项价格上限。

检查间隔允许 **1～600秒的整数，默认1秒**，前端和后端均校验，**从上一轮开始时计时**，另加0～12%随机延迟。一轮本身要打开页面、设置筛选、读取列表，通常需要几秒到十几秒；一轮超过间隔时，下一轮在上一轮结束后立即开始，所以默认的1秒就是连续检查。异常时按次数退避，多个任务串行使用浏览器。该方案是周期检查，不能保证在资源刚空出的同一瞬间捕获，也不能保证竞争成功。监测时限只限制尚未提交任务的等待时间，已提交实例会继续被核对。

### 发现空闲 GPU 之后

已授权自动执行的任务，在同一轮内直接继续，不先通知、也不等待确认：

1. 留在刚才扫描的创建页（克隆则是克隆页），不重新打开页面、不重设筛选，选中候选主机、设置扩容、选择镜像。
2. 同时在另一个标签页读取实例列表，作为提交前的对账基线；克隆任务用同一份列表复核源实例仍存在且已关机。余额保护开启时，余额也在此时并行刷新，点击前只要求结果在15秒内。
3. 核对配置、报价与余额后点击“创建并开机”。

运行日志记录“本轮开始到点击”的秒数，以及配置核验是否沿用了扫描页面。此前的做法是先跳到实例列表、再重新打开创建页并重设全部筛选，2026-10-29 的日志显示这一段约15秒，候选在此期间被占用。新流程在真实页面上的耗时尚未测得，以日志为准。

### 没抢到时

空闲 GPU 在点击前后被别人租走时，任务不会停止。程序确认这次没有创建实例后，清除提交记录，立即继续扫描。

- 准备期间候选被占用、库存或价格变化、提交按钮变为不可用，或报价超过60秒：不点击，不计错误、不退避，立即进入下一轮。
- 点击“创建并开机”后，程序观察页面最多15秒：
  - 跳回实例列表，且列表中恰好多出一个与本次配置相符的新实例：记为创建成功，继续核对开机。
  - 跳回实例列表，但读取列表失败或没有唯一的新实例：仍记为已受理（不会被当成结果不明），等新实例出现在列表中；仍无法认定时转为“等待绑定核对”，不会再次创建。
  - 页面停留在表单，出现明确的失败提示（例如 AutoDL 右上角标题为“错误”的“该主机已租满，请更换主机重新创建实例”），或余额不足、GPU 架构等已识别的弹窗：程序隔约4秒两次读取完整实例列表。都没有提交前基线之外的实例，就确认未创建，清除本次提交记录并立即继续监测；出现了基线之外的实例时不自动绑定（平台已提示失败，这个实例可能属于别的任务或你手动创建的），保留提交记录，请你核对后绑定。这一核对大约需要10秒，用于避免重复扣费。按钮仍在加载时出现的失败提示不立即当作结果，等加载结束再判断。
  - 出现未识别的弹窗、15秒内页面没有可识别的变化，或“创建并开机”按钮一直在加载（AutoDL 下单后会每秒查一次新实例，最长约1分钟；程序继续等到约65秒）：平台可能仍在处理，程序保留提交记录，点击约2分钟后自动读取两次完整实例列表再判断，期间不会再次创建。不立即判定“未创建”，是因为新实例可能晚一些才出现在列表中，立即判定会让下一轮再点一次而多租。
  - 实例列表出现了提交前没有、又无法认定是本次创建的实例：保留提交记录，约2分钟后自动再核对；仍无法认定时转为“等待绑定核对”，请你核对后绑定。读取列表失败时30秒后重试，连续3次失败或登录失效时交给你。
- 提示涉及余额、实名、权限、配额等账户问题时，确认未创建后转为“需要处理”，不反复点击。
- 被平台拒绝下单的主机暂时不选，下一轮先试其他主机。主机列表只显示空闲 GPU，看不到这台主机的存储是否已满、是否在维护；只按价格挑选时，2026-10-30 00:42～00:43 同一台 311机（显示空闲 4/8）因“当前主机存储库存已满”被连续选中 5 次。现在存储、维护、驱动或 CUDA 不支持等原因暂停 30 分钟；“已租满”、点击后没有结果等原因从 2 分钟起，同一台再被拒绝时加倍（4、8、16 分钟），最长 30 分钟。没有其他合格主机时继续监测，到时自动再试。暂不选择的主机写在本轮日志和任务详情中；恢复任务不会清除这份记录，它到时自动失效。
- 有的主机要求多卡起租（例如“该主机2卡起租”，列表里看不到）。选中这类主机后 AutoDL 会把 GPU 数量改大或让原数量不可选；程序发现数量不再是任务要求的卡数时不点击，这台主机 30 分钟内不选，改试其他主机。
- 出现 AutoDL 的 GPU 架构提示（例如“Blackwell架构的GPU（如50系列等）…需使用CUDA12.8及以上版本的CUDA”）时，程序不会代为点“继续”；确认未创建后停止任务并写明原因，因为换主机也不会通过。
- 连续两次点击后都没有识别出结果（均已确认未创建）时提醒一次，请你看一眼专用浏览器中的提示，任务仍继续监测。2026-10-29 21:12 之前的版本在这种情况下会把任务转为“需要处理”，已改掉。10分钟内被拒绝5次时也提醒一次，仍继续监测。
- 被拒绝或确认未创建后30分钟内，若实例列表出现了与任务相符（地区、型号、卡数）、提交前没有的新实例，不论在哪台主机，都可能是延迟创建：下一次点击前发现时，停止自动提交，请到 AutoDL 核对后再恢复任务，避免多租。若此时另一台主机已经点击成功，程序在核对新实例期间发现别的主机上也多了一个相符的新实例，会提醒一次“可能多租了一台”，请你核对，不需要的实例请自行释放（程序不会释放实例）；任务完成后不再检查。恢复任务或“停止旧任务并重建”都不会清除这30分钟的拒绝记录，只会把你核对过的那几台新实例记为已知；之后再出现其他新实例，仍会停下。
- 多个任务的型号、卡数相同且地区有重叠时，其中一个任务已点击、还没绑定到新实例前，其他任务暂不提交，避免分不清新实例属于哪个任务；已被一个任务绑定的实例不会被当成另一个任务的。
- 某个地区的地区、型号或卡数选项当前不可选（灰色）时，本轮跳过这个地区，不点击，下一轮再看；所有地区都不可选时继续监测，不停下任务。
- 这台主机给不了所需的数据盘扩容（“需要扩容”不可选，或填入的容量被页面改小）时不点击，这台主机暂时不选，改试其他主机。
- 实例名称或备注写得像实例 ID 时，程序按一行中所有形如实例 ID 的片段核对是否有新实例，不会因此把新实例看漏；同一页两行读成同一个实例 ID 时停止核对，并提示你修改名称或备注。

程序不会代为点击任何弹窗。报错提示的识别方式：点击前标记页面上已有的提示和弹窗，点击后只读取新出现的 Element / Element Plus 提示、表单校验错误、弹窗、气泡确认框，以及含“已租满”“库存不足”“创建失败”等明确失败说法的浮层。AutoDL 当前页面使用 Element Plus，余额不足和 GPU 架构提示都是 Element Plus 的确认弹窗；2026-10-29 21:00 前后的版本只认 Element UI 的弹窗样式，那时 RTX 5090 的四次点击若是这类弹窗就认不出来（是否如此无法确认）。识别规则按组件的常见结构、AutoDL 公开前端代码和用户截图中的“已租满”通知实现，没有读取真实页面 DOM。识别不到的新提示会写进日志，便于以后补充规则。

### 任务队列与运行日志

两栏布局时，任务队列与左侧表单底部对齐，任务多时在队列内部滚动；点队列右上角的“收起”可只保留标题和各状态的数量，刷新页面后保持。任务详情的运行日志按最新在上排列；往下翻看旧日志时，页面每2秒的刷新和新增的日志都不会把它弹回最上面，已勾选的数据盘核验和已填写的实例 ID 也不会被清空。

### 每轮扫描范围

| 选项 | 每轮行为 | 代价 |
| --- | --- | --- |
| 首页优先，定期完整翻页（新任务默认） | 每个所选地区先读第一页；有合格主机立即核验并按授权执行。距上次完整检查超过“完整翻页间隔”（默认20秒，可设10～3600秒）时，这一轮改为完整翻页。首轮总是完整翻页 | 只出现在后页的合格主机最多晚约一个间隔被发现 |
| 每轮完整翻页 | 每个地区读到末页，或读到合格主机为止 | 第一页没有合格主机时每轮多花翻页时间 |

AutoDL 不保证有卡主机都排在第一页。第一页可能都是有空卡但驱动 CUDA、可扩容容量或价格不符合条件的主机，合格主机在后页。因此不提供“永远只扫第一页”。现有代码在第一页找到合格主机时本来就会立即停止，“首页优先”只在第一页未命中时少翻页；打开创建页和设置筛选也占每轮时间，实际节省以运行日志中的“用时”为准。20秒默认值是用户指定的，不是测得的最优值。完整翻页的一轮本身可能就要约20秒（2026-10-29 日志：读10～13页时读列表约15秒），这时下一轮开始时已超过20秒，几乎每轮都是完整翻页，首页优先的提速作用很小；列表只有几页时两种检查会交替进行。想多做首页快速检查，可调大这个间隔。

运行日志会写明本轮是首页快速检查还是完整翻页检查、每个地区读了几页或“仅读第 1 页”、是否已到末页、读到的主机数和本轮用时。命中候选时另记一条，写明地区、型号、空闲数和单卡价，随后才进入配置与完整报价核验。只有所选地区都读到末页才会写“均已读到末页”；翻页后内容不变时记为“翻页停滞”，不当作已遍历。提交前按候选 ID 找回主机始终会翻页，不受此选项影响。旧任务和未指定扫描方式的接口请求保持每轮完整翻页。

### 复选框与型号筛选

GPU 型号筛选、创建页“需要扩容”和克隆对话框“数据盘”都按选项名称定位。程序点击一次后最多等待5秒，等待期间不重复点击；Element 组件需原生勾选与页面样式一致才算生效。型号筛选先勾选目标型号，再取消“全部”和其他型号，结束时核对只剩目标型号；目标型号禁用或页面有多组“全部”时不做改动。错误会写明是哪个选项、要勾选还是取消、最后看到的状态。

这类页面问题连续出现2次内自动退避重试，第3次转为“需要处理”并通知，均发生在付费点击之前。恢复检查或正常完成一轮后重新计数。若反复出现，请把任务日志中的完整错误发给维护者，以便判断页面规则。

普通容器实例通过网页可见内容操作；没有套用容器 Pro 管理 API，也没有调用未公开的库存接口。网页改版、登录过期、验证码、配置无法识别都会暂停并提示处理。请勿在程序工作时同时修改专用浏览器内的表单。

## 通知

- **站内消息**：始终记录，显示任务名、事件、结果和投递情况。
- **桌面提醒**：点击“开启桌面提醒”并在自己的浏览器允许通知；需要页面打开。
- **AutoDL 微信**：先在 AutoDL 绑定微信，在本地“通知设置”填写开发者 Token。请求使用官方微信消息接口及原始 `Authorization`，不是 Bearer。程序每15秒最多发起一次请求、滚动24小时最多50次，限速信息跨重启保留。
- **HTTPS Webhook**：填写你的接收地址和可选 Bearer Token。发送 JSON，包含 `id`、`event`、`title`、`name`、`content`、`taskId`、`timestamp`，并设置稳定的 `Idempotency-Key`。接收端应去重。

各渠道失败最多尝试5次，成功的渠道不重复发送。外部服务已接收但本地未收到响应时，重试仍可能产生重复消息；微信渠道没有服务端幂等保证。启用渠道后，会尝试投递本地仍未成功投递的真实任务历史消息；旧演练任务的消息不会投递。

通知在资源符合、提交、完成、到期、失败或需要人工处理时产生。没有库存时静默检查，不逐次发送状态消息。外部通知未配置时只能在控制台查看结果。

## 提交结果不明、重启和数据保留

提交之前落盘保存已有实例基线、候选和操作意图；点击按钮之前再次持久化提交边界。点击之后发生断线或异常时，保留记录并进入对账，不再次创建。

只有确认平台已跳回实例列表、且提交前基线之外出现唯一匹配地区、型号、数量和目标主机的新实例时才自动绑定。不能明确归属时在 AutoDL 核对后人工填写目标实例 ID。不要在程序提交期间另行手工创建相同配置的实例，以免混淆归属；这不是平台服务端提供的幂等事务。

重启时，未进入点击的操作暂停；已知目标只核对原目标；点击结果不明的任务保留记录等待人工绑定。不要通过删除 `.runtime` 或新建另一个任务来重试不明确的付费提交。

本地运行文件位于 `.runtime/`：

- `state.json`：任务、提交记录、日志、消息、通知设置和可选 AI 设置。主动选择记住的模型 Key、余额 Token 和通知凭据以 Windows DPAPI 密文保存，公共状态不回显；不记住时不写入秘密。
- `browser-profile/`：专用浏览器的登录信息。程序不读取你日常浏览器的现有凭证。
- `server.lock`：阻止多个抢卡进程使用同一份状态。

`.runtime/` 已被 `.gitignore` 排除。不要将该目录或其中 Token、登录信息发给他人。服务停止后可将整个目录备份到你自己的安全位置；迁移运行电脑时先确认原进程已退出。加密凭据通常不能跨电脑/Windows 用户解锁，迁移时应重新配置；不要为迁移删除含提交记录的任务状态。源实例的数据保留期限、复制规则和扩容计费以平台当前页面为准，应自行保留必要备份。

## 本地使用的安全边界

每位用户在自己的电脑、自己的未共享项目目录运行一份服务。正式启动只监听127.0.0.1；接口要求随机本地令牌，并核对请求来源、Host端口及回环连接，拒绝代理转发与浏览器跨来源子请求。页面设置了CSP、禁止嵌入和静态资源白名单。登录在AutoDL官方页面完成，API Key和Token不以原文回填。

这些措施用于本地工具的网页访问控制，**没有实现多人账号认证或租户隔离**。其他电脑上的普通用户没有项目提供的共享入口；同一电脑上的恶意程序、其他有能力访问本机端口的用户，以及获得当前用户权限的代码仍可能控制本地服务。Windows DPAPI保护已选择记住的凭据，不能防住以同一用户身份运行的恶意代码；专用浏览器资料也需要按敏感文件保护。

不要将本地端口通过公网、局域网代理或隧道共享。分发压缩包时排除.runtime、登录资料及自己的配置秘密。模型与通知是可选外发渠道，应由用户选择可信接收方。详细威胁模型、保护范围与退出行为见 [docs/SECURITY.md](SECURITY.md)。目前没有进行独立渗透测试。

```powershell
npm.cmd run check
```

`test:ui`、`test:login-ui`、`test:models-ui`、`test:tasks-ui`、`test:account-ui`、`test:images-ui`、`test:submit-ui` 和 `test:plan-ui` 使用隔离状态目录与本地合成页面，需要可用的 Playwright Chromium、Windows Chrome 或 Edge；浏览器测试也可用 `AI_TEST_BROWSER` 指定可执行文件。它们不会读取实际 `.runtime`、登录 AutoDL、租用 GPU、调用模型服务或发送外部通知；`test:submit-ui` 还在浏览器中禁用全部域名解析。截图分别保存到 `docs/` 中对应页面文件。`eval:plan` 从 GitHub 读取评测项目的 README 与依赖文件（缓存在 `.cache/`，不提交）；模型组用你自己的 API Key（环境变量 `AI_EVAL_API_KEY`，可选 `AI_EVAL_PROVIDER`、`AI_EVAL_MODEL`、`AI_EVAL_BASE_URL`），按服务商计费，13 个用例合计约 1.1 万 Token；加 `--rules-only` 只评测规则，不调用模型。

`src/env-plan.mjs` 为环境与选卡规划（规则提取、GPU 规格、求解与官方镜像选择），`src/ai.mjs` 为可选模型助手，`src/engine.mjs` 为任务状态机，`src/adapters/autodl.mjs` 为可见网页适配器，测试用合成适配器位于 `tests/fixtures/synthetic-adapter.mjs`，`src/notifications.mjs` 为通知，`public/` 为控制台。`eval/` 为规划评测集与结果。`examples/` 提供两份真实任务配置参考（程序不自动导入这些文件），`TEST_REPORT.md` 记录本次验证范围。
